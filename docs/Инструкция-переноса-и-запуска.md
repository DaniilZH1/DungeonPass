# Перенос DungeonPass на другой компьютер

Инструкция переносит существующую базу PostgreSQL вместе с аккаунтами и записями, затем запускает приложение на новом Windows-ПК.

## Что потребуется

- Git.
- Node.js не ниже 22.12 (либо 20.19 и выше).
- PostgreSQL на новом компьютере. Для простого переноса установите ту же основную версию PostgreSQL, что и на старом.
- Доступ к старому компьютеру и его базе `dungeon_pass`.

## 1. Сделайте резервную копию на старом ПК

Откройте PowerShell и выполните команду. Если имя пользователя PostgreSQL отличается от `postgres`, замените его:

```powershell
pg_dump -h localhost -p 5432 -U postgres -Fc -d dungeon_pass -f "C:\DungeonPass-backup\dungeon_pass.backup"
```

Перед этим создайте папку `C:\DungeonPass-backup`. Утилита может запросить пароль PostgreSQL. Дождитесь завершения команды и проверьте, что файл `dungeon_pass.backup` появился.

Безопасно перенесите этот файл на новый ПК. В нём содержатся данные аккаунтов и записи хранилища, поэтому не выкладывайте его в открытый доступ.

Также сохраните значение `VAULT_ENCRYPTION_KEY` из `.env` старого ПК и передайте его на новый компьютер защищённым способом. **Для восстановления паролей сервисов нужен именно прежний ключ. Новый ключ не подойдёт.** Сам файл `.env` целиком не публикуйте.

## 2. Установите проект на новом ПК

Откройте PowerShell:

```powershell
git clone https://github.com/DaniilZH1/DungeonPass.git
cd DungeonPass\dungeonpass.client
npm ci
```

Установите на новом ПК PostgreSQL той же основной версии, что использовалась на старом. Команды `pg_dump` и `pg_restore` должны быть доступны в PowerShell. Если Windows их не находит, запустите их из папки `bin` установки PostgreSQL, например `C:\Program Files\PostgreSQL\16\bin`.

## 3. Создайте пользователя и пустую базу

В pgAdmin откройте Query Tool для базы `postgres` и выполните команду, подставив свой длинный пароль для приложения:

```sql
CREATE ROLE dungeonpass_app LOGIN PASSWORD 'ЗАДАЙТЕ_ПАРОЛЬ';
```

Затем отдельно создайте базу. Выполняйте команду вне транзакции:

```sql
CREATE DATABASE dungeon_pass OWNER dungeonpass_app;
```

Если роль уже существует, не создавайте её повторно. Убедитесь, что у неё есть пароль, и используйте его в `.env`.

## 4. Восстановите резервную копию

В PowerShell выполните команду от имени администратора PostgreSQL:

```powershell
pg_restore -h localhost -p 5432 -U postgres -d dungeon_pass --no-owner --no-acl "C:\путь\dungeon_pass.backup"
```

Замените путь на фактическое расположение файла. Утилита запросит пароль пользователя `postgres`. Восстанавливайте копию в пустую базу `dungeon_pass`.

После восстановления в pgAdmin откройте Query Tool базы `dungeon_pass` и выдайте приложению доступ:

```sql
GRANT SELECT, INSERT, UPDATE, DELETE
  ON ALL TABLES IN SCHEMA public TO dungeonpass_app;

GRANT USAGE, SELECT
  ON ALL SEQUENCES IN SCHEMA public TO dungeonpass_app;
```

## 5. Проверьте миграцию схемы

В проекте файл `database-migration.sql` добавляет уникальное ограничение на email в таблице `public.users`. Сначала проверьте, что оно уже есть:

```sql
SELECT conname, pg_get_constraintdef(oid) AS definition
FROM pg_constraint
WHERE conrelid = 'public.users'::regclass
  AND contype = 'u';
```

Если в результате уже есть `UNIQUE (email)`, миграция применена — ничего запускать не нужно.

Если такого ограничения нет, проверьте, не дублируются ли email:

```sql
SELECT email, COUNT(*)
FROM public.users
GROUP BY email
HAVING COUNT(*) > 1;
```

Если запрос вернул строки, сначала разберитесь с дубликатами. Иначе миграция завершится ошибкой. Если дубликатов нет, откройте `dungeonpass.client/database-migration.sql` в Query Tool базы `dungeon_pass` и выполните его содержимое.

## 6. Настройте `.env`

В PowerShell, находясь в `DungeonPass\dungeonpass.client`, создайте локальный файл настроек:

```powershell
Copy-Item .env.example .env
```

Сгенерируйте новый `AUTH_TOKEN_SECRET`:

```powershell
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
```

Откройте `.env` и укажите строку подключения к новой базе и секреты:

```env
DATABASE_URL=postgres://dungeonpass_app:ПАРОЛЬ_РОЛИ@localhost:5432/dungeon_pass
PORT=3001
AUTH_TOKEN_SECRET=СЮДА_ВСТАВЬТЕ_НОВЫЙ_СЕКРЕТ
VAULT_ENCRYPTION_KEY=СЮДА_ВСТАВЬТЕ_СТАРЫЙ_КЛЮЧ
```

В `VAULT_ENCRYPTION_KEY` вставьте без изменений прежний ключ из старого `.env`. Не генерируйте для перенесённой базы новый ключ. Если пароль роли содержит символы `@`, `:`, `/`, `#` или `%`, их нужно кодировать для URL; проще задать роли длинный пароль из латинских букв и цифр.

## 7. Соберите и запустите приложение

В той же папке выполните:

```powershell
npm run build
npm run start
```

Откройте `http://localhost:3001`. Проверка базы доступна по адресу `http://localhost:3001/api/health`; нормальный ответ — `{"ok":true}`. Остановить сервер можно сочетанием `Ctrl+C` в PowerShell.

Войдите с существующей учетной записью. Если вход не проходит, проверьте подключение к базе и права роли. Пользователи и записи должны перенестись вместе с резервной копией.

## После переноса

- Храните резервную копию базы и `VAULT_ENCRYPTION_KEY` отдельно и в защищённом месте.
- Не коммитьте `.env` или файл `.backup` в Git.
- Удалите временную резервную копию с нового ПК после проверки переноса, если она больше не нужна.
- При смене `AUTH_TOKEN_SECRET` потребуется войти заново. Данные аккаунтов и пароли сервисов сохраняются, если восстановлена база и указан прежний `VAULT_ENCRYPTION_KEY`.
